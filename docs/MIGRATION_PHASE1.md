# 新系統第一階段：學生為本遷移預覽與介面方向

## 階段目標

本階段以目前版本為基礎，先建立**只讀遷移預覽**。工具只讀取使用者從舊系統匯出的 JSON 備份，產生班級、學生 ID、出缺勤、平時考、段考、收費資料摘要，以及同名候選清單；不會連線寫入 Firebase、不會合併學生，也不會刪除資料。

第一階段沒有可直接使用的舊備份檔時，系統不會自行推測正式資料。請先在目前版本按「備份」匯出 JSON，再在本機執行預覽工具。

```bash
node scripts/migration-preview.mjs /path/to/教學紀錄備份.json ./migration-preview
```

輸出目錄會產生 `migration-preview.md` 與 `migration-preview.json`。Markdown 報告供人工閱讀，JSON 報告供後續匯入工具使用。預覽工具的安全旗標會明確記錄 `writesFirebase: false`、`mergesStudents: false` 與 `deletesData: false`。

## 同名學生處理原則

姓名只作為搜尋與顯示資訊，不能作為唯一識別。新系統以不可重複的學生 ID 作為身分鍵；若同一姓名出現不同學生 ID，預覽報告會列出學校、年級、班級與資料來源，交由人工判定。

| 預覽情況 | 第一階段處理 |
|---|---|
| 相同學生 ID 出現在多個班級 | 視為同一學生的多筆班級 enrollment，保留各班日期與分組 |
| 不同 ID、姓名相同、學校或年級也相近 | 列為同名候選，不自動合併 |
| 不同 ID、姓名相同但無法確認 | 保留為不同學生，等待人工確認 |
| 只有歷史紀錄、已不在班級名單 | 列為紀錄孤兒，先不刪除 |

## 預定的新資料方向

學生主檔會保存姓名、學校、年級與唯一 ID；班級 enrollment 會保存加入日、停班日、復課日與數A／數B／未分組。出缺勤、平時考、段考與收費仍保留班級脈絡，避免同名學生在不同班級的紀錄互相污染。舊版 `classIndex` 與 `studentIndex` 在遷移完成前仍保留，不進行破壞性覆寫。

## 新介面方向：明亮、活潑、可長時間使用

新系統採用**學習手帳風格的明亮工作台**：以暖白作為底色，搭配珊瑚橘、湖水綠、靛藍與金黃色作為功能色。不同功能用色彩區分，但文字與狀態仍維持高對比；學生姓名、學校、分組與日期會使用清楚的標籤，不以裝飾取代資訊。

首頁會以班級卡片與今日課程摘要為主，卡片使用柔和圓角、輕陰影與小幅度 hover 動畫；出缺勤使用較醒目的狀態色帶，成績使用分數色階與分組標籤，行事曆使用事件色點及學校標籤。動畫只用於頁面切換、抽屜與提示，不影響快速點名。

## 月曆／週曆切換

行事曆保留月曆與新增的週曆兩種檢視。切換按鈕固定在行事曆標題區，目前選取日期在兩種檢視間保持不變。

| 檢視 | 顯示內容 | 操作 |
|---|---|---|
| 月曆 | 整月日期、國定假日、大考、自訂事件與多日事件色帶 | 上一月、下一月、回到今天、點日期查看事件 |
| 週曆 | 週一至週日七欄，按日期排列課程、假日與事件 | 上一週、下一週、回到今天、點日期新增或查看事件 |

週曆中的多日事件會以同色區段連續呈現；不連續日期事件則在各自日期顯示相同事件色標。國定假日與大考使用固定色彩，校外教學、校內段考與自訂事件可使用事件色標辨識。手機以垂直查看為主，桌機與平板則提供較寬的七日欄位。

## 第一階段的安全邊界

本階段只產生本機預覽檔，不會新增 Firebase 專案、不會切換正式 App 的資料庫設定，也不會修改使用者目前資料。待同名候選清單經人工確認後，才進入下一階段的匯入預演；匯入預演仍應先寫入隔離資料庫或獨立測試環境，不直接覆蓋正式資料。
