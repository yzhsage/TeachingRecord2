# 補習班情境的資料模型

## 核心原則

補習班的班級不是學校班級。**同一補習班班內可以同時有不同學校的學生**，所以學校不能放在班級資料；學校應放在學生於某個年度／班級的學習資料中。

班級的正式辨識只使用不可變的 `classId`。畫面上的班級名稱可以隨年度、年級或課程調整，但不會改變 `classId`，也不會因為名稱相同而重複使用另一個 ID。

## 班級資料

```text
classes/{classId}
  id                  // 系統自動產生，永久不變
  subject             // 數學、理化、自然等
  track               // 可選：數A、數B
  displayName         // 目前顯示名稱，例如「國三理化班」
  displayNameHistory[]
    academicYear      // 例如 2026
    gradeLabel        // 例如 國二、國三
    displayName       // 該年度顯示名稱
  createdAt
  archivedAt
```

若今年的國二理化班明年整班升為國三理化班，系統可保留同一個 `classId`，並新增一筆名稱歷史。若明年另外開一個新的國二理化班，系統建立新的 `classId`。即使兩個班在畫面上都叫「國二理化班」，內部也不會混淆。

這裡不強制使用「學期」，因為目前上下學期不影響您的班級辨識與資料操作。若未來真的需要，可再以選填欄位加入，不作為 ID 或主要判斷條件。

## 學生年度班級資料

```text
students/{studentId}/classRecords/{recordId}
  id                  // 系統自動產生
  classId             // 補習班班級 ID
  academicYear        // 學年度或您指定的年度
  gradeLabel          // 該年度的年級
  school              // 該年度就讀學校
  group               // 數A、數B或空白
  joinDate
  endDate
  status              // active、ended、uncertain
```

同一學生每進入一個新的年度／班級關係，就建立一筆新的 `classRecord`；學生主檔的 `studentId` 不變。年級與學校都是這筆年度資料的屬性，不放在學生 ID 裡。

例如陳宥晴：

| 年度 | 班級顯示 | `classId` | 學校 | 年級 |
|---|---|---|---|---|
| 今年 | 國二理化班 | 系統建立的 A 班 ID | 港明 | 國二 |
| 明年 | 國三理化班 | 同一 A 班 ID（若整班延續） | 港明 | 國三 |
| 後年 | 高一物化班 | 系統建立的新高中班 ID | 港明 | 高一 |

例如廖婕茹：

| 年度 | 班級顯示 | `classId` | 學校 | 年級 |
|---|---|---|---|---|
| 今年 | 國二理化班 | A 班 ID | 安南 | 國二 |
| 明年 | 國三理化班 | A 班 ID | 安南 | 國三 |
| 後年 | 高一物化班 | 新高中班 ID | 港明 | 高一 |

## 人工確認只需要做什麼

人工確認不需要輸入任何 ID，也不需要填延續群組。系統會顯示每一列舊資料的姓名、原班級、學校、年級與年度，使用者只需選擇：

| 畫面選項 | 意義 |
|---|---|
| 建立新學生 | 這列是新學生；系統自動產生新的 `studentId` |
| 與既有學生合併 | 從搜尋結果選擇同一位學生；系統沿用該學生的 `studentId` |
| 尚未確認 | 暫時保留，系統禁止匯入 |

班級確認只需對「同一班是否延續」做一次選擇：在年度班級清單中選擇「沿用這個班」或「建立新班」。使用者不輸入 ID；系統自動產生或沿用 `classId`。

## 建議畫面

學生確認頁面應以一位候選學生為主卡片，而不是讓使用者填一串代碼。卡片顯示「姓名、學校、年級、舊班級、年度、紀錄數」，下方列出可能相同的既有學生卡片。使用者按下「同一位學生」或「建立新學生」即可完成判定。

班級確認頁面則顯示年度班級時間軸，例如「2026 國二理化班 → 2027 國三理化班」。使用者只需要按「沿用同一班」或「建立新班」，不需要理解 `classId`、`lineageId` 或 UUID。

所有 ID 在按下確認後由系統自動產生，且操作紀錄保存原始 occurrence、判定時間與判定結果。未確認的資料永遠不會被寫入正式新資料庫。
